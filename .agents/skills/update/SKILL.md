# 운영하기 (update)

이미 만든 웹앱의 내용만 바꾸는 일이다. 화면 모양은 건드리지 않는다.

## 준비
1. `내사이트/data/site.js` 의 stage 와 type, `data/app-data.js` 를 읽는다. stage 가 "landing" 이면 랜딩페이지 한 장 판이라 장소 · 항목 추가는 하지 않고 「지금은 랜딩페이지 판이에요. 서비스 화면은 신청을 보고 나중에 만들어요」라고 한 줄 말한다. 바꿀 곳은 내 유형 칸(map · list · calc · quiz · log)의 items 다. 없으면 「먼저 $start 로 웹앱을 만들어 주세요」 한 줄만 말하고 멈춘다.
2. AGENTS.md 「브랜드 규칙」의 내 사이트 주소를 확인한다.

## 문장별로 하는 일
| 받은 문장 | 할 일 |
|---|---|
| 신청 폼 연결해 주세요: (주소) | site.js 의 formUrl 에 그 주소만 넣는다. 주소가 https:// 로 시작하고 구글 폼(docs.google.com/forms · forms.gle) 또는 네이버 폼(form.naver.com)인지 본다. 아니면 「폼의 「보내기」 · 「공유」에서 나온 주소를 붙여 주세요」라고 묻는다. 넣은 뒤 「다시 올려 주세요」를 안내한다 |
| 장소 추가해 주세요: … / 항목 추가해 주세요: … | app-data.js 내 유형 칸 items 끝에 한 줄 더한다. 받은 이름 · 동네 · 설명만 쓰고, 모르는 칸은 빈 글자로 둔다. 지도형은 동네(area) 칸을 비우지 않는다. 사용자가 말하지 않았으면 좌표가 속한 동 이름을 OpenStreetMap 에서 확인해 넣는다. app-data.js 에 이미 있는 동네 이름(예: 쌍문동)과 같은 곳이면 그 이름을 그대로 쓴다(거르기 버튼이 동네 이름으로 생기기 때문). 지도형 좌표는 사용자가 준 곳이면 OpenStreetMap 에서 확인하고, 아니면 그 동 중심 좌표를 쓴다. 사용자가 준 실제 장소에는 sample 을 붙이지 않는다 |
| …를 지워 주세요 | 그 이름의 줄만 지운다. 같은 이름이 둘이면 어느 것인지 묻는다 |
| 예시를 다 지워 주세요 | sample: true 인 줄만 지운다 |
| 공지 한 줄 바꿔 주세요: … | notice 값만 바꾼다. 「공지 지워 주세요」면 빈 글자로 둔다 |
| 다른 곳에 올릴 파일로 만들어 주세요 (: 새 주소) | 새 주소를 받았으면 site.js 의 url 에 먼저 넣는다(사이트 지도 · 미리보기 그림 주소가 여기서 나옴). 내사이트 폴더에서 `npm run build` 로 `out` 폴더를 만들고, 그 안의 파일을 통째로 `내사이트_올릴파일_YYYYMMDD.zip` (my-project 폴더 바로 아래)으로 묶는다. 그리고 세 줄로 안내한다: ① zip 을 풀어 나온 파일을 호스팅의 맨 위 폴더(루트)에 올립니다 ② 올릴 곳 예: Netlify · Cloudflare Pages · 카페24 같은 웹호스팅 ③ 주소 뒤에 /폴더 가 붙는 곳(예: 깃허브 페이지의 저장소 주소)은 화면이 깨지니 쓰지 않습니다. 서버가 필요 없는 파일이라 어디서나 열린다고 한 줄 덧붙인다 |
| 내 도메인 연결하고 싶어요 | 도메인은 사용자가 직접 산다(가비아 · 카페24 등). 산 도메인이 있으면 내사이트 폴더에서 `npx vercel domains add (도메인)` 을 실행하고, Vercel 이 알려 주는 DNS 값(A 또는 CNAME)을 도메인 산 곳의 DNS 설정에 넣으라고 한 줄씩 안내한다. 연결되면 site.js 의 url 을 새 도메인으로 바꾸고 다시 올린다 |
| 다시 올려 주세요 | 먼저 내사이트 폴더에서 `npm run build` 로 오류가 없는지 보고, `npx vercel --prod` 로 같은 Vercel 주소에 다시 올린다. 처음이라 주소가 없으면 AGENTS.md [5]의 Vercel 규칙을 따른다 |

- 지어낸 가게 이름 · 전화번호 · 영업시간 · 후기 · 숫자는 넣지 않는다.
- app · components · globals.css 는 고치지 않는다. site.js 는 formUrl 만 고친다. 모양을 바꿔 달라는 말이 따로 있을 때만 고친다.

## 확인과 기록
1. 고친 뒤 내사이트 폴더에서 `npm run build` 로 깨지지 않았는지 확인한다(쉼표 · 따옴표 · 괄호). 개발 화면(`npm run dev`)이 켜져 있으면 저절로 바뀐다고 한 줄 알린다.
2. `작업파일/운영기록.md` 맨 아래에 한 줄을 더한다. 파일이 없으면 만든다.
   형식: `- 2026-10-12 · 장소 추가 · 쌍문역 3번 출구 앞 (쌍문동)`
3. 사용자에게 두 줄로 알린다. 무엇을 바꿨는지 한 줄, 그리고 「인터넷 주소에도 보이게 하려면 「다시 올려 주세요」를 보내세요」(다시 올린 경우는 주소).
