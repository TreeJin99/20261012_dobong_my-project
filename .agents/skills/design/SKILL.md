# 내 사이트 다듬기 (design)

내 사이트의 「옷」만 갈아입히는 일입니다. 뼈대(화면 짜임 · 글 · 기능)는 그대로 두고, 색 · 글꼴 · 글자 크기 · 여백 · 모서리만 바꿉니다.
레퍼런스는 사용자가 직접 찾아 옵니다. 남의 사이트는 「느낌」만 빌리고 글 · 사진 · 로고 · 코드는 가져오지 않습니다.

## 0. 먼저 묻기 (인터뷰)
한 번에 하나씩 묻습니다. 답마다 「제가 이해한 건 이거예요: … 맞으면 '네'」로 되묻습니다. 이미 말한 것은 다시 묻지 않습니다. 묻고 답한 것은 `작업파일/인터뷰기록.md` 맨 아래에 「## design · 날짜」로 더합니다.
① 지금 화면에서 가장 마음에 안 드는 곳은 어디인가요?
② 참고할 사이트 주소나 화면 캡처를 붙여 주세요. 없으면 「마음에 드는 사이트를 직접 찾아서 주소나 캡처를 붙여 주세요」라고만 하고 기다립니다. 사이트를 대신 골라 주거나 목록을 내밀지 않습니다.
③ 그 사이트에서 무엇이 좋았나요? (색 · 글꼴 · 여백 · 버튼 모양 · 큰 제목 중에서)
④ 꼭 지킬 것이 있나요? (기본값: 내 좋아하는 색은 그대로. 그대로면 '네')

## 1. 레퍼런스 살피기
- 주소를 받으면 그 페이지에서 ③에서 좋다고 한 것만 살핍니다. 페이지를 못 읽으면 「화면 캡처를 붙여 주세요」라고 합니다.
- 캡처를 받으면 그림에서 같은 것을 읽습니다.
- 바꿀 것을 한 줄씩 말하고(예: 바탕을 크림색으로, 버튼 모서리를 둥글게) 「이대로 바꿀까요? 맞으면 '네'」로 한 번 묻습니다.

## 2. 입히기
1. 바꾸기 전에 `내사이트/app/globals.css` 맨 위 `:root { … }` 묶음 전체를 `작업파일/디자인기록.md` 맨 아래에 「## 바꾸기 전 · 날짜」로 그대로 복사합니다(되돌리기용).
2. 고치는 곳은 `내사이트/app/globals.css` 하나뿐입니다. 먼저 `:root` 의 값을 바꾸고, 모자라면 이미 있는 규칙의 값(크기 · 여백 · 모서리 · 굵기)만 바꿉니다. 새 className 을 만들지 않습니다.
3. 건드리지 않는 것: app · components 의 jsx 파일, className, data 폴더의 글, 새 꾸러미(npm 패키지).

## 3. 확인
1. 내사이트 폴더에서 `npm run build` 로 오류가 없는지 봅니다.
2. 글자와 바탕이 잘 읽히는지(본문 · 버튼 글자) 확인하고, 흐리면 색을 조금 진하게 고친 뒤 알려 줍니다.
3. 휴대폰 폭에서 제목이 넘치지 않는지 봅니다.
4. 바꾼 것을 표 한 장(칸 · 전 · 후)으로 보여 주고 `작업파일/디자인기록.md` 에 「## 바꾼 뒤 · 날짜」를 더합니다.
5. 끝에 안내합니다: 마음에 안 들면 「디자인 되돌려 주세요」(디자인기록.md 의 「바꾸기 전」으로 :root 를 되돌림) · 인터넷 주소에도 보이게 「다시 올려 주세요」.
