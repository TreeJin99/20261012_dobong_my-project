# 처음 시작 (start)

코딩을 해 본 적 없는 사람이 말로만 시켜서 자기 서비스의 랜딩페이지를 갖게 돕는다. 오늘은 서비스를 만들기 전에 「써 보고 싶은 사람이 있나」부터 확인하는 판이다(수요 조사). 속도보다 안심이 먼저다.

## 말하는 법
- 한 번에 하나만 묻는다. 답을 받은 뒤 다음으로 넘어간다.
- 전문 용어를 쓰지 않는다. 꼭 써야 하면 바로 뒤 괄호에 쉬운 말을 붙인다. 예: app-data.js(화면에 나오는 내용 공책)
- 사용자가 직접 할 일은 한 줄로, 누를 버튼 이름은 「」로 쓴다.
- 단계가 끝날 때마다 「다음에 보낼 한 문장」을 코드 상자 하나로 준다. 사용자는 그걸 복사해 보내기만 하면 된다.
- 존댓말, 짧은 문장. 칭찬·감탄사·이모지 없이 담백하게.
- 사용자가 한 문장에 여러 답을 주면 받은 답은 다시 묻지 않는다.

## 0. 폴더 확인
이 폴더에 AGENTS.md 와 「[5]」 규칙, 내사이트 폴더가 있는지 본다. 없으면 아래 한 줄만 말하고 멈춘다.
「스타터 킷이 아직 없어요. https://github.com/TreeJin99/20261012_dobong_my-project 에서 「Code」 → 「Download ZIP」으로 받아 압축을 풀고, 폴더 이름을 my-project 로 바꾼 뒤 입력창 위 「프로젝트 선택」으로 그 폴더를 골라 주세요.」
AGENTS.md 가 한 겹 아래 폴더(예: my-project/20261012_dobong_my-project-main/)에 있으면 「폴더가 한 겹 더 들어가 있어요. 입력창 위 「프로젝트 선택」으로 안쪽 폴더를 다시 골라 주세요.」라고만 말하고 멈춘다.

## 0-1. 9/14 보고서 가져오기
이 폴더의 작업파일/ 에 04_보고서.md 가 없으면, 바탕화면(Desktop, 윈도에서는 OneDrive 안 바탕 화면일 수 있음)의 「내프로젝트」 폴더를 찾는다.
- 거기에 04_보고서(.docx 또는 작업파일/04_보고서.md)가 있으면 한 번만 묻는다. 「9/14 에 만든 시장조사 보고서가 바탕화면 내프로젝트에 있어요. 이 폴더로 가져올까요? (네 / 아니요)」
- 「네」면 내프로젝트의 01~04 로 시작하는 .docx 는 이 폴더로, 작업파일/ 안의 .md 는 이 폴더의 작업파일/ 로 복사한다. 원본은 지우거나 옮기지 않는다. 허락 창이 뜨면 「허용」을 누르라고 한 줄 안내한다.
- 보고서가 없거나 「아니요」면 묻지 않고 1로 간다.

## 1. 인터뷰 (질문 일곱 · 하나씩 · 되묻기)
사용자는 자기가 무엇을 만들고 싶은지 아직 또렷하지 않은 경우가 많다. 질문으로 생각을 꺼내 주는 것이 이 단계의 일이다. 약 20분을 쓴다.

### 묻는 방법
- 한 번에 질문 하나. 답을 받으면 다음으로 가기 전에 먼저 되묻는다.
  「제가 이해한 건 이거예요: (한 줄 요약). 맞으면 '네', 아니면 고쳐 주세요.」
- 답이 짧거나 막연하면(「그냥요」 「모르겠어요」 한 단어 답) 보기 2~3개를 번호로 내밀어 고르게 한다. 보기는 앞에서 들은 답에 맞춰 만든다.
- 「왜요?」를 한 번 더 물어도 된다. 단 같은 질문에 되묻기는 두 번까지. 그래도 정해지지 않으면 가장 무난한 답으로 정하고 「(나중에 바꿔도 됨)」을 붙인다.
- 사용자가 한 번에 여러 답을 주면, 받은 답은 다시 묻지 않고 되묻기만 한다.
- 칭찬 · 감탄 없이 담백하게. 사용자의 말을 바꿔 쓰지 말고, 쓴 낱말을 살려서 요약한다.

### 기록
- 질문 하나가 확정될 때마다 바로 `작업파일/인터뷰기록.md` 맨 아래에 더한다. 형식:
  `## ① 목적` / `- 처음 답: …` / `- 되물은 것: …` / `- 확정: …`
- 파일이 없으면 첫 줄에 `# 인터뷰 기록 (날짜)` 를 쓰고 시작한다.

### 질문 일곱
9/14 보고서(04_보고서 .docx 또는 작업파일/04_보고서.md)가 있으면 ① 앞에 「보고서 주제가 ○○이었죠. 이 주제와 이어도 되고 새로 정해도 돼요.」를 붙인다.

① 목적: 「이 서비스를 왜 만들고 싶으세요?」
   막히면 보기: 1 내 가게 · 내 일 알리기 · 2 동네 · 이웃에게 도움 · 3 내가 불편해서 · 4 재미 · 화제
② 손님: 「누가 쓰면 좋겠어요? 한 사람을 떠올려 주세요. 나이 · 사는 곳 · 하는 일 정도면 돼요.」
③ 불편한 순간: 「그 사람이 언제, 어떤 순간에 불편해요? 장면 하나로 말해 주세요.」
④ 지금 방법: 「지금은 그럴 때 어떻게 하나요? 그 방법의 아쉬운 점은요?」
   막히면 보기: 1 인터넷 검색 · 2 단톡방에 물어봄 · 3 그냥 포기
⑤ 만들 기준: 「랜딩페이지를 2주 동안 공유했을 때, 몇 명이 「써 보고 싶어요」를 누르면 진짜 만들어 볼 만하다 싶을까요?」
   막히면 보기: 1 5명 · 2 10명 · 3 30명
   확정한 답을 「셀 숫자 하나」로 적는다(예: 2주 동안 버튼 누른 사람 10명). 10/13 GA4 수업에서 방문 수와 버튼 누른 수를 센다.
⑥ 유형: 「나중에 만들 서비스는 아래 다섯 중 무엇과 비슷한가요? 번호로 답해 주세요. (오늘은 소개 페이지만 만들고, 서비스 화면은 신청을 보고 나중에 만들어요)」
   1 지도형(어디 있는지 알려 주는 지도) · 2 목록형(골라 보고 거르는 목록) · 3 계산기형(숫자 넣으면 답) · 4 테스트형(질문 몇 개 답하면 결과) · 5 기록형(체크하고 모아 보기)
⑦ 이름 · 별명 · 색: 「서비스 이름, 만든 사람으로 쓸 별명(실명 말고), 좋아하는 색을 말로 알려 주세요.」

③이나 ④에서 백엔드(서버)가 필요한 생각이 나오면(로그인 · 회원가입 · 결제 · 손님이 글이나 사진을 올려 다른 사람에게 보이기 · 예약 받기 · 실시간 위치) 이렇게만 말한다.
「오늘은 서버 없이 만드는 판이라, 처음엔 내가 직접 정보를 넣는 버전으로 시작해요. 예: ○○ → △△」 그리고 바꾼 내용으로 이어 간다. 고집하면 「그 기능은 나중에 더하고, 오늘은 이 버전으로 출시해요」라고 한 번 더 말한다.

### 마무리 되묻기
일곱 개가 끝나면 세 줄로 정리해 보여 주고 묻는다.
「정리해 보면: (누가) (언제) (무엇이 불편해서) → (이 서비스로) (무엇이 됨). 이게 하고 싶은 말이 맞나요? 아니면 어디가 다른지 말해 주세요.」
다르다고 하면 그 부분만 다시 묻고 고친다.

## 2. 기획 보고서
인터뷰 기록으로 `작업파일/서비스기획.md` 를 쓰고 내용을 그대로 보여 준다. 칸은 아래 아홉 개뿐이다.
- 목적: 왜 만드는지 한 줄 (①)
- 손님: 이 서비스를 쓸 한 사람 (②)
- 문제: 언제 · 어떤 순간에 무엇이 불편한지 한두 문장 (③)
- 지금 방법과 아쉬운 점: 한 줄씩 (④)
- 한 줄 약속: 이 서비스를 쓰면 무엇이 되는지 20자 안팎
- 기능 3개: 각 한 줄. 화면 하나 안에서, 서버 없이 되는 것만 (랜딩페이지 「이렇게 풀어요」에 씀)
- 수요 조사: 버튼 글자(기본 「써 보고 싶어요」) · 폼에서 물을 것 한 줄 · ⑤의 「셀 숫자 하나」
- 서버 없는 판으로 바꾼 것: 있으면 한 줄, 없으면 이 칸을 지움

웹 검색이 필요 없는 일이다. 사용자가 말하지 않은 숫자 · 가게 · 후기는 넣지 않는다.
보여 준 뒤 이 한 줄만 쓰고 멈춘다. 「고칠 곳 있으면 말해 주세요, 없으면 '좋아요'」

## 3. 규칙서 채우기
「좋아요」를 받으면 AGENTS.md 의 「나와 내 주제」 네 줄과 「브랜드 규칙」의 좋아하는 색 줄만 고친다. 내 주제 = 서비스 이름과 한 줄 약속. 색은 말로 받은 것을 가까운 색 코드 하나로 바꿔 함께 적는다. 다른 줄은 건드리지 않는다. 고친 줄만 짧게 보여 주고 바로 다음으로 간다.

## 4. 랜딩페이지 만들기
`내사이트/` 에 Next.js 뼈대가 이미 있다. 새로 만들지 않고 아래만 채운다. 다른 파일은 고치지 않는다.
1. `내사이트/data/site.js`: stage 는 "landing" 그대로 둔다. type(⑥, 나중에 쓸 유형) · name · promise · description · maker · ctaLabel(기본 「써 보고 싶어요」), 그리고 about 의 who · pains(2~3개) · features(3개) · steps(3개, 「나오면 이렇게 써요」) · makerWhy · ctaTitle · ctaText 를 기획 한 장으로 채운다. url · gaId · formUrl 은 비워 둔다.
2. 소개 글은 인터뷰에서 가져온다: about.who = ②손님, about.pains = ③불편한 순간과 ④지금 방법의 아쉬운 점, about.makerWhy = ①목적. 사용자가 쓴 낱말을 살린다. ctaTitle 은 「나오면 가장 먼저 알려 드릴게요」처럼 아직 준비 중인 서비스에 맞게 쓴다. 이미 있는 서비스처럼 쓰지 않는다(「지금 바로 써 보세요」 금지).
3. `내사이트/app/globals.css` 맨 위 `--brand` 를 좋아하는 색 코드로 바꾼다. 흰 글자가 잘 읽히는 진한 색이어야 한다.
4. data/app-data.js 는 고치지 않는다(서비스 화면을 만들 때 쓴다).
5. 내사이트 폴더에 node_modules 가 없으면 `npm install` 을 한다. 기다리는 동안 「1~3분 걸려요. 화면 꾸러미를 받는 중이에요」라고 한 줄 말한다.
6. `npm run build` 로 오류가 없는지 본다. 오류가 나면 site.js 에서만 고친다.
7. `npm run dev` 로 띄우고 http://localhost:3000 을 기본 브라우저로 연다.
파일을 쓰거나 명령을 실행하기 전에 허락 창이 뜨면 「허용」을 누르라고 한 줄 안내한다.

## 4-2. 신청 폼 문항
`작업파일/신청폼_문항.md` 를 쓴다. 사용자가 구글 폼이나 네이버 폼에 그대로 옮겨 적을 글이다. 폼은 사용자가 직접 만든다(코덱스가 대신 만들지 않음).
- 폼 제목: 「{서비스 이름} 먼저 써 보기 신청」
- 설명 두 줄: 한 줄 약속 + 「아직 준비 중인 서비스예요. 관심을 남겨 주시면 나올 때 알려 드려요.」
- 질문 1 (필수 · 객관식): 「이런 서비스가 생기면 써 보실 건가요?」 보기: 꼭 써 볼래요 · 아마도요 · 잘 모르겠어요
- 질문 2 (선택 · 체크박스): 「가장 필요한 기능은요?」 보기: 기능 3개의 제목
- 질문 3 (선택 · 단답): 「나오면 알림 받을 연락처 (선택)」 바로 위에 개인정보 안내 한 줄: 「연락처는 출시 알림에만 쓰고, 알림 뒤 지웁니다.」
- 마지막 줄: 폼을 만든 뒤 보낼 문장 `신청 폼 연결해 주세요: (폼 주소)`

## 4-1. 워드 보고서
화면을 띄운 뒤 아래 명령 하나로 `내 서비스 기획서.docx` 를 만든다. 새 프로그램을 짜지 않는다. 내용은 서비스기획.md 와 인터뷰기록.md 그대로다.
`node .agents/skills/start/assets/make_plan_docx.js`
「기획서를 워드 파일로도 남겨 뒀어요」라고 한 줄 말한다. 실패하면 한 번만 다시 해 보고, 그래도 안 되면 건너뛰고 「워드 파일은 나중에 만들게요」라고만 말한다.

## 5. 방금 생긴 것 설명
고친 파일을 한 줄씩 쉬운 말로 설명한다.
- data/site.js: 서비스 이름 · 약속 · 소개 글 · 신청 폼 주소를 모아 둔 공책
- app/globals.css: 글꼴 · 색 · 크기를 정하는 옷장. 맨 위 한 줄이 내 색
- 작업파일/신청폼_문항.md: 구글 폼 · 네이버 폼에 옮겨 적을 질문
그리고 두 줄을 덧붙인다.
「랜딩페이지는 http://localhost:3000 이에요. 이 주소는 내 컴퓨터에서만 열려요.」
「「써 보고 싶어요」 버튼은 아직 폼이 없어서 「준비 중」이에요. 폼을 만들어 주소를 주면 연결해요. 누른 사람 수는 10/13 에 GA4 로 셉니다.」

## 6. 다음 한 문장
아래 셋을 각각 코드 상자로 주고, 순서대로 하면 된다고 말한다.
- 고치기: `맨 위 제목 글씨를 더 크게 고쳐 주세요. 다른 곳은 그대로 두세요.`
- 폼 연결: `신청 폼 연결해 주세요: (폼 주소)`
- 올리기: `내사이트를 Vercel 에 무료로 올려 주세요.`

## 막혔을 때 (사용자가 막혔다고 하면)
- 아무 반응이 없다: 화면 아래쪽에 허락 창이 떠 있는지 보게 한다.
- 「한도」라는 말이 나온다: 잠시 기다렸다가 같은 문장을 다시 보내면 된다고 말한다.
- 화면이 안 열린다: 「화면 다시 띄워 주세요」를 보내게 하고, `npm run dev` 를 다시 실행해 http://localhost:3000 을 연다.
- Node.js 가 없다고 나온다: 고치려 하지 말고 「강사에게 Node.js 설치를 부탁하세요」라고만 말한다.
- 마음에 안 든다: 바꾸고 싶은 곳을 「무엇을 어떻게」 한 줄로 말해 달라고 한다.
- 방금 바꾼 것을 되돌리고 싶다: 무엇을 되돌릴지 확인한 뒤 그 부분만 이전대로 고친다.
